Overview

Problem. Video questions need different evidence: ordering needs scene sequences, layout needs keyframe positions, movement needs tracks over time, “how many” needs de-duplicated instances, and speech or sound needs transcripts and audio tags. Running every model for every question costs GPU and API calls that the question does not need.

Idea. A query classifier (GPT-4o mini, zero-shot prompt) assigns each question to exactly one of five categories: temporal, spatial, spatio-temporal, counting, or audio. Only the matching branch executes; the other four are never invoked and their models are never loaded. Results per video are cached in a per-video ChromaDB collection, so repeated questions about the same video reuse previously computed chunks. Hybrid retrieval (dense + lexical) selects evidence, and an answer generator (GPT-4o mini with a category-specific instruction) produces the final answer.

If the classifier returns an invalid label, the system falls back to spatial.

Architecture

Classifier and answer generation always run. Exactly one of the five branches runs per question.

Branch details

Temporal

Trigger: ordering, sequence, before/after timing.

Models: PySceneDetect (content-based scene detection, no ML weights); GPT-4o-mini captioner, default instruction “Describe this scene in one sentence.”

Output: timestamped, ordered list of scene captions (one mid-scene frame per scene).

Execution: local + API, only if classified temporal.

Spatial

Trigger: layout or position at a single moment. Also the fallback category.

Models: CLIP ViT-B/32 (openai/clip-vit-base-patch32) keyframe selection with K-Means (k=8); GPT-4o-mini captioner with layout instruction “Describe the layout and position of objects in this frame.”; Grounding DINO-tiny (IDEA-Research/grounding-dino-tiny), raw query as detection target.

Output: per-keyframe layout captions plus grounded object list.

Execution: local + API, only if classified spatial.

Spatio-temporal

Trigger: how something moved or changed position over time.

Models: RT-DETR R50VD (PekingU/rtdetr_r50vd_coco_o365); custom IoU / SORT-style tracker (Hungarian assignment, local).

Output: per-track start position, end position, and time span.

Execution: local only, only if classified spatio-temporal.

Counting

Trigger: “how many” questions.

Models: RT-DETR R50VD with the same IoU tracker, used to de-duplicate repeated sightings into one tracked instance per class.

Output: exact unique-instance count per object class, with one supporting frame per class. Generator instruction: report the exact number, do not estimate.

Execution: local only, only if classified counting.

Audio

Trigger: speech, dialogue, or non-speech sound events.

Models: Whisper large-v3-turbo (openai/whisper-large-v3-turbo) timestamped transcription; AST (MIT/ast-finetuned-audioset-10-10-0.4593) top-5 sound-event tags.

Output: timestamped transcript segments annotated with audio event tags. Generator instruction: use the transcript and audio tags.

Execution: local only, only if classified audio.

Limitations

  • Small evaluation set: 150 queries total (50 per dataset). Percentages therefore have wide uncertainty; every chart shows counts alongside percentages.
  • Tested: per-query outputs (question, ground-truth answer, predicted answer, video duration) for ActivityNetQA, MovieChat-1K, and MusicAVQA samples.
  • Not tested here: classifier routing accuracy (source JSONs do not record the classifier’s chosen label), retrieval recall, per-branch latency or cost, or comparison against baselines. No aggregate metrics were present in the source files, so none are reported.
  • Category groupings on this page are a keyword heuristic for browsing; they are not the system’s routing labels.

Reproduce

  1. Place a JSON file of (video_id, query) pairs where the pipeline can read it, and put the video files in the Drive videos folder the pipeline resolves IDs against. Missing videos are logged and skipped.
  2. Provide an OpenAI API key for the GPT-4o-mini calls (classification, captioning, answer generation). Vision, audio, and embedding models run locally; model weights load lazily on first use.
  3. Run the pipeline notebook (query classification → cache check → one branch → BGE embedding into per-video ChromaDB → hybrid BGE + BM25 retrieval → answer generation) and collect the output JSON.
  4. Sync site data with python3 scripts/sync_data.py (copies results/*.json to docs/data/), then serve locally: python3 -m http.server --directory docs.
